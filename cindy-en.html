01Overview

Cindy

Cindy is an open-source AI assistant. My work spans capability extensions, cross-device use, and interaction proposals: what users can do, where they start, how they understand progress, and how they receive results.

02The Problem

How do capabilities, interfaces, and delivery workflows become one usable experience?

As an agent product expands, users need to find the right tools, understand task progress, and resume work across devices. Plugins, interfaces, and delivery workflows need to be designed and validated together.

04The System

Carry product decisions into real-workflow validation.

Define scope first
Clarify goals, capabilities to preserve, core acceptance, and supplementary risks, and record the environment, target version, and uncovered cases.
Follow the user path
For attachments: reply → receipt → preview → download/open. For plugin cards: initial load, revisions, themes, and buttons. For quotations: return to a group and switch during sending.
Review the final behavior
Compare the original requirement, implementation, and final behavior to check whether capabilities remain. Record regressions and residual issues, then carry useful checks into documentation and the next iteration.

06Reflection & Scope

Turn one-off fixes into repeatable product judgment.

  1. Frame the problem before choosing the deliverable

    Plugins, personal Skills, interaction prototypes, and client changes address different scopes. Study existing capabilities and user situations before choosing a minimum deliverable.

  2. Preserve real states in visuals and interactions

    SkillHub sorting and installation states, group retry and reassignment, and attachment receipt and download each need explicit behavior and failure paths.

  3. Use evidence to state the delivery stage

    Record prototypes, tests, reviews, merges, releases, and real-client usability separately. Retain gaps in authorization, device coverage, and migration validation.
