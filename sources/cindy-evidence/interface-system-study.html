本节同步最近一次源码核对结论，更新说明口径；不表示这些能力都在今天新增，也不代表已安装客户端或生产环境已经验证。

结论：伙伴拥有自己的长期 Home，但不等同于当前项目文件夹。
伙伴的长期记忆按伙伴 ID 归属；项目文件夹是某次工作读写文件的地点。更换项目，不会自动切换整套伙伴记忆；两位伙伴在同一项目工作，也不会因此共用记忆。

2. 这几层不应混在一起

层保存内容与边界
伙伴长期记忆memories/ 中的 Markdown 分片；USER.md 是用户画像，存储层单独处理，不当作普通分片。
派生索引MEMORY.md 与 fts.db；长期记忆仍以分片文件为基础。digest 不进入常规 MEMORY.md 精选索引。
工作记忆账本Home 下的 working-memory.json：线索、承诺、等待、纠正及近期完成，供换窗或压缩后交接；不是授权。
任务上下文与历史各私聊主任务、话题、群专线与分工任务分别管理；完整聊天记录不等于长期记忆或当前模型窗口。
项目 / workspace文件执行与交付地点；分工可以使用群项目目录，不因此改写伙伴的记忆归属。

3. 旧数据怎样迁过来

新路径是 Bot Home / memories；旧伙伴记忆曾保存在账号根下的 maker-memory 目录。

旧：<账号根>/maker-memory/
    bot-<可读片段>-<哈希16位>/
              ↓ 首次打开时惰性复制
新：<账号根>/bots/<伙伴ID>/memories/
  1. 复制符合记忆分片命名规则的 Markdown；新目录已有同名文件时保留新文件。
  2. MEMORY.md、meta.json、fts.db 等派生 / 宿主状态不从旧记忆库照搬，目标重新建立。
  3. 写入 .cindy-memory-migration-v1.json 完成标记；旧目录保留用于回退，不持续双向同步。
  4. 另一套 Home 迁移把早期未按账号隔离的 bots/<ID> 复制到账号根；写入 .cindy-home-migration-v1.json，只补缺失内容并保留源目录。

所以“旧目录仍在”不等于当前还从旧目录读写，也不能仅凭文件存在证明迁移已完成。

4. 开关、群聊与文件写入边界

  1. 伙伴记忆独立于全局 Maker Memory。不沿用其全局开关和全局清空入口；伙伴自己的 config.memory 仍可关闭记忆。
  2. 使用同一伙伴记忆键。运行时按 bot ID 生成 bot:<ID>；工具优先使用宿主绑定的键，不因 workingDir 改变而重新分区。
  3. “只聊天”群授权是例外。该路径明确关闭记忆、清空用户画像及额外目录；不能把“同一伙伴”理解成所有群都能读它的私有资料。
  4. Home 不全部暴露给原始文件工具。文件工具只获得 workspace；memories / skills 由宿主类型化工具维护。用户可以纠正的身份文件和工具写入权限是不同入口。
