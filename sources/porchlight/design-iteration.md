## 2. 页面和交互

主页从上到下：品牌与原型说明 → 露台画面 → 一句 Homi 提示 → 短期计划 / 长期记忆 → 底部输入。

- 按住说话，拖向目标时高亮，松开结束录入；识别结束后进入相应草稿。
- 不拖动时显示可校对的识别文字。文字发送后也可选择去向；该选择是原型对未接入模型的明确回退。
- 计划：新增需确认时间；已有卡片直接改时间并保存；对话修改先选择已有计划。
- 记忆：展示理解内容、图片、图片中的位置；拖入后选择新增或覆盖已有条目。
- 视频：打开人与人对讲入口。当前只演示按住状态，不发音、不接设备。
- 触屏通过 Pointer Events 拖动；键盘可按空格/回车录入，再点去向按钮；支持文字拖放。

**本次设计选择，不是会议逐字规定：**温暖浅色、低饱和紫色语音按钮、弹层而非跳转页面、保存确认、本地示例数据、区域下拉选项、结束/暂停操作。图片位置关联只是可编辑标签，不是图像定位或视觉理解结果。

## 3. 与上一版的差异

上一版对纪要的理解偏向管理台，功能层级过多。这次撤掉五页导航与复杂首页，详情全部按需打开。旧版保留在 v1/，便于对照。

最重要的纠正：视频上的语音交互是与快递员或朋友对话，不能实现成向 AI 提问画面内容。

## 4. 实现边界与验收

- 已实现：布局、弹层、卡片与时间编辑、图文位置关联、确认保存、语音/文字切换、指针拖动与文字拖放、本地持久化。
- 浏览器识别：代码已接浏览器 SpeechRecognition，支持选择识别语言；真实麦克风、权限、网络及中英识别质量未实测。浏览器可能把音频交给其识别服务。
- 待实现：第三方 ASR、大模型理解与自动修改、实时视频、双向对讲、服务端存储及反馈学习。
- 赛题 Web SDK 当前提供直播和帧订阅，没有对讲接口。需团队确认官方扩展通路或其他可用 SDK，再实现传声；不将访客对话悄悄改成 AI 问答。
- 示例卡片与图片不是实际检测结果；时间为示例，不代表设备任务正在执行。
- 验证结果见 verification-results.json，测试页 verify.html 会在所打开浏览器中重置本原型数据，应在独立测试配置内运行。


本轮验证：21/21 项检查通过；桌面截图已检查。新版手机截图操作被拒绝，未完成视觉复核；390px 宽度自动检查通过。语音识别时序用模拟识别器验证，硬件链路未测试。
